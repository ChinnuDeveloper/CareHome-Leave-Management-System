### Use Case ID:UC-001
| **Use Case Name** | Submit Leave Request |
|---|---|
| **Related Functional Requirement ID** | FR-001 |
| **Primary Actors** | Employee |
| **Secondary Actors** | System |
| **Description** | Allows an employee to submit a leave request by selecting a leave type, start date, and end date, viewing calculated total remaining hours, and optionally providing a reason before submitting. |
| **Preconditions** | 1. Employee is logged into the system.<br>2. Employee has an active leave balance. |
| **Assumptions** | 1. Leave Type is pre-configured in the system.<br>2. Total hours is auto-calculated based on selected Start Date and End Date.<br>3. Remaining hours reflects real-time balance before submission. |
| **Trigger** | Employee clicks "Request Leave" from dashboard screen. |
| **Main Flow** | 1. System displays the "Leave Request" form.<br>2. Employee selects a Leave Type from the dropdown.<br>3. Employee selects a Start Date using the date picker.<br>4. Employee selects an End Date using the date picker.<br>5. System auto-calculates and displays Total Hours based on selected dates.<br>6. System displays remaining hours.<br>7. Employee optionally enters a reason.<br>8. Employee clicks "Submit".<br>9. System validates the entered data.<br>10. System deducts requested hours and creates the leave request with status "Pending".<br>11. System closes the form and confirms submission. |
| **Alternative Flows** | A1 – Cancel Request: At any point before submission, employee clicks "Cancel". System discards entered data and closes the form without saving.<br>A2 – Close via X: Employee clicks the "X" icon at top-right; system prompts to discard unsaved changes and closes the form. |
| **Exception Flows** | E1 – Leave Type Not Selected: If employee clicks Submit without selecting a Leave Type, system displays a validation error.<br>E2 – Missing Start/End Date: If either date field is blank, system displays a validation error.<br>E3 – Invalid Date Range: If End Date is earlier than Start Date, system displays a validation error.<br>E4 – Insufficient Remaining Hours: If Total Hours requested exceeds Remaining Hours, system displays an error and blocks submission.<br>E5 – Past Date Selection: If Start Date is earlier than the current date, system displays a validation error. |
| **Postconditions** | 1. Leave request is created with status "Pending" and appears under "My Leave Requests".<br>2. Remaining hours balance is updated to reflect the pending request. |
| **Business Rules** | BR1 – End date must not be earlier than start date.<br>BR2 – Employee cannot apply for leave dates that overlap with an existing pending or approved request.<br>BR3 – Leave days requested cannot exceed available leave balance. |

### Use Case ID:UC-006

| **Related Functional Requirement ID** |	FR-006 |
| **Primary Actors** |	System |
| **Secondary Actors** |	Manager(triggers the event via UC-003) |
| **Description** |	Automatically deducts the requested leave hours from an employee's remaining leave balance the moment a manager approves their leave request, ensuring the balance stays accurate without manual intervention. |

| **Assumptions** |	1. Balance update happens synchronously as part of the approval transaction.<br> 2. Remaining Hours field on both the Dashboard (UC-005) and Leave Request form (UC-001) reflects the updated balance immediately after approval.<br>3. Only one leave request can be approved at a time per transaction. |

System deducts Requested Hours from the employee's Remaining Hours balance.<br>4. System updates the leave request status to "Approved." <br>5. System persists the updated balance and request status to the database. 6. System reflects the updated Remaining Hours on the employee's Dashboard (UC-005) and any future Leave Request submission (UC-001).|
|**Alternative Flows** | |	
| **Exception Flows** |	E1–Insufficient Balance at Time of Approval: If Remaining Hours is less than Requested Hours ,system blocks the update, does not approve the request, and returns an error to the Manager.<br>E2 – Balance Update Failure: If the system fails to update the balance due to a technical error, system rolls back the request status change (request remains "Pending") and displays an error to the Manager.<br>E3 – Concurrent Approval Conflict: If two approvals are processed simultaneously for the same employee causing a balance conflict, system applies concurrency control to ensure only valid deductions are applied, rejecting the one that would cause a negative balance.|

### Use Case ID:UC-007
| **Use Case Name** |	Generate Annual Leave Entitlements |
| --- | --- |
| **Related Functional Requirement ID** |	FR-007 |
| **Primary Actors** |	Manager |
| **Secondary Actors** |	System |
| **Description** |	Allows a manager to generate annual leave entitlements for a selected financial year by specifying a calculation rule (weekly hours × multiplier), which the system applies across all departments to recalculate each employee's annual leave balance.|

| **Assumptions** |	1. Each employee's weekly contracted hours are already stored in their employee profile.<br>2. The multiplier value is a standard, manager-editable figure display.<br>3. Generating entitlements for a year applies to all employees in a single action.|

Manager selects the desired Year  from the dropdown.<br>4. System displays the "Calculation Rule — Weekly Hours × Multiplier" field with a default multiplier value.<br>5. Manager reviews or updates the Multiplier value.<br>6. Manager clicks "Generate."<br>7. System validates the selected Year and Multiplier.<br>8. System recalculates each employee's annual leave entitlement as (Weekly Contracted Hours × Multiplier), applied across all departments.<br>9. System updates each employee's Remaining Hours balance for the selected financial year.<br>10. System closes the modal and confirms successful generation.|
| **Alternative Flows** |	A1– Cancel Generation: Manager clicks "Cancel" before clicking Generate; system discards changes and closes the modal without recalculating entitlements. <br>A2 – Close via X: Manager clicks "X"; system closes the modal without saving. | **Postconditions** |	1. Each employee's annual leave entitlements recalculated and updated for the selected financial year, based on Weekly Contracted Hours × Multiplier.<br>2. Updated balances are immediately reflected on Employee Dashboards (UC-005) and Leave Request forms (UC-001). <br>3. The generation action is logged for audit purposes.|
| **Business Rules** |	BR1: Entitlement = Weekly Contracted Hours × Multiplier, applied uniformly across all departments.<br>BR2: Only users with Manager role can access and perform this configuration.<br>BR3: Multiplier must be a positive numeric.<br>BR4: Generation should ideally occur once per financial year, typically before or at the start of that year, though re-generation is permitted with confirmation. |

| **Description** |	Allows an eligible employee to request one day of Birthday Leave, to be taken either on their actual birthday or at any point during their birthday week, in line with the care home's leave policy, separate from their standard annual leave entitlement. |
| **Preconditions** |	1. Employee is logged into the system.<br>2. Employee's date of birth is on file in their employee profile.<br>3. Employee is eligible for Birthday Leave.<br>4. Employee has not already used their Birthday Leave entitlement for the current year. |
| **Assumptions** |	1. "Birthday Leave" exists as a distinct Leave Type option separate from Annual Leave in the leave request form.<br>2. System can determine the employee's birthday week based on their date of birth.<br>3. Birthday Leave is capped at exactly one day per year and does not deduct from the employee's standard annual leave balance. |
| **Trigger** |	Employee selects "Birthday Leave" as the Leave Type on the "Leave Request" form and submits a request. |
| **Main Flow** |	1. Employee navigates to "Request Leave" and selects "Birthday Leave" from the Leave Type dropdown.<br>2. System displays the Leave Request form with Start Date and End Date fields.<br>3. Employee selects a single date that falls on their birthday or within their birthday week.<br>4. System validates that the selected date falls within the employee's eligible birthday-week window.<br>5. System validates that the employee has not already used their Birthday Leave for the current year.<br>6. Employee optionally enters a Reason.<br>7. Employee clicks "Submit." <br>8. System creates the Birthday Leave request with status "Pending." <br>9. System displays a confirmation message to the employee. |
| **Alternative Flows** |	A1– Cancel Request: Employee clicks "Cancel" before submitting; system discards entered data and returns to the dashboard. <br>A2– Select Birthday Itself: Employee selects the exact birthday date,system validates and proceeds identically to any other day within the eligible window. |
| **Exception Flows** |	E1– Date Outside Birthday Week: If the selected date does not fall on the employee's birthday or within their birthday week, system displays a validation error and blocks submission.<br>E2– Birthday Leave Already Used: If the employee has already taken their one day of Birthday Leave for the current year, system displays an error and blocks submission.<br>E3 – Employee Not Eligible: If the employee does not meet policy eligibility criteria for Birthday Leave, system displays an error and blocks submission. <br>E4 – Multiple Days Selected: If Employee attempts to select a date range spanning more than one day, system displays a validation error, since Birthday Leave is limited to a single day. <br>E5 – Overlapping Request: If the selected date overlaps with another existing pending/approved leave request, system displays an error. |
| **Postconditions** |	1. A Birthday Leave request is created with status "Pending" for manager review.<br>2. The request does not affect the employee's standard Annual Leave Remaining Hours balance.<br>3. Once approved, the employee's Birthday Leave entitlement for the year is marked as used. |
| **Business Rules** |	BR1: Birthday Leave is limited to one day per employee per year. <br>BR2: The selected date must fall either on the employee's actual birthday or within the defined "birthday week".<br>BR3: Birthday Leave does not deduct from the employee's standard Annual Leave entitlement.<br>BR4: Birthday Leave requests follow the same approval workflow as standard leave requests.<br>BR5: Eligibility for Birthday Leave is governed by the care home's leave policy.|
